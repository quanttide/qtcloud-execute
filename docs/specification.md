# 执行云事件风暴（Event Storming）

> 基于：docs/dev-guide/index.md（双视图 + AI 提炼管道）
> 日期：2026-08-23

## 领域事件（已发生的橙色事件）

| 事件 | 说明 |
|------|------|
| 日志已记录 | 用户/系统记下一条事实（业务 × 日期） |
| 日志已分组 | 日志归入业务（qtdata/qtclass/qtcloud） |
| 提炼草稿已生成 | AI 从日志流生成档案更新草稿 |
| 提炼已确认 | 人确认/修改草稿（AI 加工、人挑选） |
| 档案已更新 | 状态视图变化（推进程度/阻塞） |
| 重点已调整 | 优先级变化（AI 建议 + 人确认） |
| 阻塞已标记 | 卡点被显式标出（如 ACR 凭证） |

## 命令（触发动作）

| 命令 | 触发者 | 产出的领域事件 |
|------|--------|---------------|
| 记录日志 | 用户 | 日志已记录 |
| 按业务分组 | 系统（自动） | 日志已分组 |
| 生成提炼草稿 | AI（定时/手动） | 提炼草稿已生成 |
| 确认提炼 | 用户 | 提炼已确认 |
| 调整优先级 | AI 建议 + 用户确认 | 重点已调整 |
| 查看档案 | 用户 | （读操作） |
| 标记阻塞 | 用户 | 阻塞已标记 |

## 聚合（黄色——一致性边界）

```
JournalEntry（日志条目）    —— 事实，不可变（只追加）
  ├── content / date / business
Business（业务组）          —— qtdata / qtclass / qtcloud
  └── 聚合日志流 + 档案集
ProfileItem（档案条目）     —— 状态（重点/进度/阻塞），可变
  ├── business × function（business/product/operation）
  └── 由提炼更新
Distillation（提炼任务）    —— 日志 → 档案的转换
  └── 草稿状态（生成 → 确认 → 应用）
```

## 角色（参与者）

- **用户**（创始人/成员）：记录日志、确认提炼、调整优先级
- **AI 提炼引擎**：生成草稿、建议优先级
- **业务组**（qtdata/qtclass/qtcloud）：日志与档案的分组维度

## 核心事件流

```
记录日志 → 日志已记录 → 按业务分组 → 日志已分组
    ↓
AI 提炼（生成草稿 → 提炼草稿已生成）
    ↓
用户确认/修改 → 提炼已确认 → 档案已更新
    ↓
优先级变化（AI 建议 + 人确认）→ 重点已调整 → 阻塞已标记
    ↓
用户查看档案 → 全局状态可见（判断依据）
```

## 关键规则（从事件风暴得出的设计约束）

1. **日志不可变**：JournalEntry 只追加（事实不改）
2. **档案可变但须经确认**：ProfileItem 只能由"提炼已确认"更新（AI 不直接改状态）
3. **优先级是判断不是事实**：重点调整必须人确认（AI 只建议）
4. **分组即业务**：Business 是日志与档案的共同维度（双视图同构的根）
5. **提炼是异步管道**：草稿 → 确认 → 应用，三步状态机（Distillation）
