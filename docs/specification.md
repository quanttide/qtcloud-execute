# 执行云事件风暴（Event Storming）

> 基于：docs/dev-guide/index.md（双视图 + AI 提炼管道）
> 日期：2026-08-23

## 领域事件（已发生的橙色事件）

| 事件 | 说明 |
|------|------|
| 任务已记录 | 一条事项进入系统（内容/来源/时间） |
| 任务已分组 | 任务归入清单（业务/职能/日期维度） |
| 任务已确认 | 人对任务状态/内容确认（AI 加工、人挑选） |
| 清单已更新 | 任务清单变化（增删/重排） |
| 优先级已调整 | 任务的优先级变化（AI 建议 + 人确认） |
| 阻塞已标记 | 任务卡点被显式标出（如 ACR 凭证） |

## 命令（触发动作）

| 命令 | 触发者 | 产出的领域事件 |
|------|--------|---------------|
| 记录任务 | 用户 | 任务已记录 |
| 分组任务 | 系统（自动） | 任务已分组 |
| 确认任务 | 用户 | 任务已确认 |
| 调整优先级 | AI 建议 + 用户确认 | 优先级已调整 |
| 查看清单 | 用户 | （读操作） |
| 标记阻塞 | 用户 | 阻塞已标记 |

## 聚合（黄色——一致性边界）

```
Task（任务）              —— 一个事项，最小单元
  ├── title（标题——一句话概括）
  ├── content（内容/描述）
  ├── status（待办/进行中/blocked/完成）
  └── priority（优先级，AI 建议 + 人确认）

TaskList（任务清单）       —— 一组任务的容器
  ├── 按业务分组（qtdata/qtclass/qtcloud）
  ├── 按维度视图（日期流 / 状态档案）
  └── 只通过 Task 操作（清单是视图，不是独立实体）
```

## 角色（参与者）

- **用户**（创始人/成员）：记录日志、确认提炼、调整优先级
- **AI 提炼引擎**：生成草稿、建议优先级
- **业务组**（qtdata/qtclass/qtcloud）：日志与档案的分组维度

## 核心事件流

```
记录任务 → 任务已记录 → 分组任务 → 任务已分组
    ↓
AI 提炼（从日志/素材生成任务草稿）
    ↓
用户确认/修改 → 任务已确认
    ↓
优先级变化（AI 建议 + 人确认）→ 优先级已调整 → 阻塞已标记
    ↓
用户查看清单 → 全局状态可见（判断依据）
```

## 关键规则（从事件风暴得出的设计约束）

1. **清单是视图不是实体**：TaskList 不独立存在——只通过 Task 操作（分组/重排是视图行为）
2. **任务状态须经确认**：AI 不直接改任务状态（AI 加工、人挑选）
3. **优先级是判断不是事实**：优先级调整必须人确认（AI 只建议）
4. **分组即业务**：业务（qtdata/qtclass/qtcloud）是清单的分组维度
