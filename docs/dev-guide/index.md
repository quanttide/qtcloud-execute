# 执行云设计思路：双视图 + 提炼管道

> 来源：2026-08-23 执行档案体系（journal/profile 结构）推演

## 核心洞察

执行云不是"任务清单"，是**双视图 + AI 提炼管道**：

```
journal（时间轴——发生了什么）      profile（状态视图——现在是什么）
维度：业务 × 日期（流水账）         维度：业务 × 职能（结构档案）
```

- **journal = 事实**：今天做了什么——时间组织，不可改
- **profile = 状态**：重点在哪、推进到什么程度——职能组织，是判断
- **关系**：journal 是原料，profile 是提炼——单向演进（日志 → 档案）

## 产品结构

### 双视图

| 视图 | 对应 | 内容 |
|------|------|------|
| **日志流** | journal | 时间轴——今天发生了什么（业务分组 × 日期） |
| **档案视图** | profile | 全局状态——业务重点、推进进度（业务 × 职能） |

打开顺序：先档案（全局状态）→ 下钻日志（细节事实）——"把事情变清晰、分类分组"。

### 业务分组

顶层按业务分（qtdata/qtclass/qtcloud）：

```
业务 /
├── 日志（时间：2026-08-23.md）
└── 档案（职能：business/product/operation）
```

### AI 提炼管道（核心价值）

AI 自动做 **journal → profile 的提炼**：

```
流水账（事实）
  ↓ AI 提炼
状态更新（"推进到什么程度"）
  ↓ AI 排序 + 人确认
档案（重点/优先级）
```

- **清单不靠人类维护**：AI 维护清单，但不是维护"做没做完"——是帮助人判断
- **优先级在档案层**：日志是事实（不能改），档案是判断（重点在这里）
- **动态优先级**：AI 根据实际情况分配优先级，人确认

## 与思考云同构

```
感知（journal 记录）→ 理解（AI 提炼 profile）→ 判断（重点/优先级）→ 行动（执行）
```

执行云与思考云是同一认知结构的两个实例——一个管"事"，一个管"想"——可共享同一套提炼引擎。

## 验证方式（最小闭环）

1. 先做：日志流（记录事实）+ 档案视图（读状态）——手工可用的最小闭环
2. AI 提炼管道：从日志自动生成档案草稿，人确认
3. 真实使用后按"砍掉验证"检验（主动用/缺了难受 = 值得做）
